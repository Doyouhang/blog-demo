# Studio：本地图文编辑器

图形界面写内容，不用再记「哪个文件放哪个目录」。

```bash
npm run studio      # → http://127.0.0.1:4331
```

只监听 `127.0.0.1`，只在自己电脑上跑，没有任何外部服务和登录。

## 它做什么

- **三种内容类型**（此间 / 收藏 / 长文）的表单，字段带必填校验
- **拖照片进来自动处理**：压到最长边 1800px、JPEG q82，按 EXIF 方向摆正
- **自动读 EXIF 填元数据**：机身、镜头、焦距、光圈、快门、ISO
- **拍摄时间自动填**：第一张照片的拍摄时间直接成为这条动态的时间
- **保存 → 提交 → 发布** 三步分开，发布单独确认

## 三个按钮的区别

| 按钮 | 做什么 | 影响 |
| --- | --- | --- |
| 保存 | 写入 `src/content/` 下的 md 和图片 | 只动本地文件 |
| 提交 | `git add -A && git commit` | 只动本地仓库 |
| 发布上线 | `git push origin main` | **会触发 Actions 部署，内容真的上线** |

发布是独立操作且有二次确认 —— 保存和上线不该是同一个动作。

## 两个坑，已经处理掉了

**EXIF 的时间不带时区。** exifr 默认按 UTC 解析，东八区直接用会整体差 8 小时。
Studio 关掉值转换拿原始字符串，按本机时区还原成快门按下的那个墙上时间。

**A7C II 机身没有 GPS。** 地点要自己填。如果照片是手机拍的（通常带 GPS），
Studio 会在日志里把坐标打出来供参考，但不会替你猜地名。

## 为什么不用 Keystatic

评估过，否决。三条理由：

1. 它注入的两个路由都是 `prerender: false`，会把纯静态站变成需要 SSR adapter
   的混合模式 —— GitHub Pages 跑不了
2. 要拉进 React + react-dom + 整个编辑器 UI，而这个站现在零框架依赖
3. **它不做 EXIF 提取，也不做图片压缩** —— 恰恰是这个编辑器的核心价值

自己写的代价反而更小：内容类型只有三种、字段很少，一个 Node 服务加一个单页就够，
而且完全独立于生产构建，Astro 配置和依赖一行都不用动。

## 字段定义在哪

`studio/schema.mjs`。加字段改这里，表单自动跟着变。

**这份描述必须和 `src/content.config.ts` 保持一致。** 两处定义不理想，但从 TS + Zod
反推字段要在运行时解析类型，代价远大于收益。兜底办法是界面上的「跑一遍校验」按钮 ——
它跑 `astro check`，对不上会立刻报错，而不是等到构建甚至上线。

## 图片放哪

- 此间：一条动态一个目录，`index.md` 和照片放在一起，删一条就是删一个目录
- 收藏：封面平铺在 `src/content/items/`

源图存的是压缩过的 JPEG 而不是 WebP —— Astro 构建时还会生成响应式 WebP，
先转一道有损再转一道是白白多丢一次画质。
